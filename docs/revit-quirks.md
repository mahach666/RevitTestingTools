# Особенности Revit для UI-тестов

Наблюдения на Revit 2022.1 с английским интерфейсом (`/language ENU`). Каждый пункт опирается на контрактные тесты (файлы в [tests/RevitUITesting.Tests/Contract/Evidence](../tests/RevitUITesting.Tests/Contract/Evidence)) или, где это сказано, только на устройство кода и модульные тесты. Контрактный прогон перезаписывает файлы доказательств. Имена вкладок сторонних надстроек и имя машины в них заменены на условные.

В каталогах `RevitIds` и `RevitTitles` у каждого значения есть уровень доказательства:

- `[Р]` проверено контрактным тестом, есть файл в `Evidence`;
- `[Э]` видно на снимке экрана;
- `[К]` взято из кода или документации;
- `[Г]` гипотеза.

## Окна и диалоги

- Модальное окно и канал. Пока Revit показывает модальное окно, главное окно недоступно (`IsWindowEnabled = false`), это записано в `save-changes-2022.txt` («Главное окно доступно: False»). `ExternalEvent` в таком состоянии не выполняется, и RevitTestHost не отвечает. Клиент получает `RevitBusyException` со списком окон Revit, а не сообщение «элемента нет». Таймаут канала при модальном окне отдельно не измерялся: вывод опирается на устройство RevitTestHost и модульные тесты клиента с поддельным сервером.
- Модальное окно в дереве UIA. Оно лежит не среди окон рабочего стола, а потомком главного окна Revit (`project-units-2022.txt`: «Project Units», ClassName `#32770`). `RevitWindows` учитывает прямых потомков главного окна типа Window, кроме `Popup`. Вложенные модальные окна (глубина 2 и больше) не видны.
- Неизвестное модальное окно. Уборка (`ResetUi`) закрывает модальные окна только из каталога (всплывающим окнам Popup она посылает Esc). Неизвестное модальное окно не трогается, тест падает с его текстом и снимком. В `HostContractTests.Unknown_modal_fails_reset_and_known_entry_closes_it` «Project Units» неизвестное окно, а запись `knownDialogs` с этим заголовком его закрывает.
- Окно «Family». Окно процесса Revit класса `Afx:…` с координатами 10000,10000 (за экраном) попадает в `All()` и в описание окон (`main-window-2022.txt`, координаты видны в `ribbon-pulldown-2022.txt`). Это не диалог.
- Вопрос о сохранении (`save-changes-2022.txt`). Заголовок «Save File», текст «Do you want to save changes to new-1.rvt?», класс `#32770`, кнопки «Да | Нет | Отмена» (Button `CCPushButton`, id `CommandButton_6`, `CommandButton_7`, `CommandButton_2`). Подписи кнопок TaskDialog не следуют языку Revit: при `/language ENU` на испытательной машине они были русскими (причина не выяснена). Поэтому «No» нажимается не по подписи, а сообщением `TDM_CLICK_BUTTON` с id 7 (`RevitIds.Dialogs.TaskDialogNoButtonId`), и только окну класса `#32770` процесса Revit. Ответ подтверждён вживую в уборке окон, в `CloseActiveDocument` и в `Quit` с изменённой моделью (файл модели при этом не перезаписан).
- «Security - Unsigned Add-In». Диалог нельзя закрыть: `WM_CLOSE` равносилен «Do Not Load», Revit стартует без надстройки, а кнопки недоступны через UIA (окна нет в дереве от корня, у кнопок нет Invoke). Поэтому при ожидании готовности `RevitApp` отвечает «Always Load» (`TDM_CLICK_BUTTON` 1001, только окнам `#32770` запускаемого процесса Revit), а `trustAddins` (DWORD в `CodeSigning`) остаётся первой линией защиты. После пересборки DLL диалог появлялся и при значении 1 (наблюдение при отладке RevitTestHost, не контрактный тест библиотеки). В контрактных прогонах диалог ни разу не появился, потому что все GUID уже были доверены, поэтому ответ библиотеки на него вживую не воспроизводился. Тот же механизм (поиск окна по pid через `EnumWindows` и `TDM_CLICK_BUTTON` 1001) подтверждён вживую скриптом [tools/serve-smoke.ps1](../tools/serve-smoke.ps1). Английский заголовок `Security - Unsigned Add-In`, русский заголовок (слова «Безопасность» и «Надстройка без подписи» через тире) и id кнопок 1001, 1002, 1003 имеют уровень `[К]`.
- Активный документ Revit API не закрывает (`close` возвращает `ACTIVE_DOCUMENT`). Модели классов тестов сменяются по схеме «открыть следующую, закрыть предыдущую», а активный документ закрывает `RevitApp.CloseActiveDocument()` через интерфейс: Ctrl+F4 по видам, на вопрос о сохранении ответ «No». Наблюдалось: у нового проекта после изменения два нажатия Ctrl+F4 закрыли вид {3D}, затем Level 1, а вопрос появился после второго.
- Выход из Revit с изменённой моделью. `Quit` шлёт `WM_CLOSE`, отвечает «No» на вопросы о сохранении и, если Revit не закрылся за `revitExitTimeoutSeconds`, убивает процесс, записав перечень окон в журнал. Наблюдалось: две изменённые модели, один `WM_CLOSE`, вопросы отвечены, Revit закрылся без `Kill` за 13 с. Без `RevitSession.End()` в `[SetUpFixture]` Revit убивается в `ProcessExit`.
- Пути `\\?\`. В процессе Revit 2022 они дают «Illegal characters in path» (старая обработка путей), поэтому `Host.Open` и `[RevitUiModel]` их отклоняют. Наблюдалось в стороннем плагине, в контрактных тестах библиотеки не воспроизводилось.

## Запуск Revit

- Переменная `REVITTESTHOST_CLI` в окружении превратила бы запуск в CLI-прогон, после которого Revit завершается сам. `RevitApp` убирает переменные CLI-режима из окружения запускаемого Revit (проверено модульным тестом, во всех живых запусках Revit стартовал в режиме сервера).
- Дескрипторы процесса тестов. `Process.Start` в .NET Framework всегда наследует дескрипторы: Revit получал stdout и stderr процесса тестов, и `dotnet test` с перенаправленным выводом не возвращался, пока жил Revit, оставленный `keepRevitOpen`. Поэтому Revit запускается через `CreateProcessW` без наследования дескрипторов. Проверено вживую: `dotnet test … > файл 2>&1` с `keepRevitOpen` вернулся, а Revit остался работать.
- Память. Revit с моделью занимает от 2 до 3 ГБ commit. При нехватке памяти лицензия инициализируется минутами, а старт может занять до 15 минут (в одном случае контейнеры Docker заняли около 15 ГБ). Живые запуски при свободном commit от 6,1 ГБ были готовы за время от 41 до 48 с. Перед запуском проверяется `minFreeCommitGb`. Если память занята WSL или Docker, решение принимает пользователь.
- DPI. Осведомлённость о DPI включается до создания `UIA3Automation` (`dpiAware: true`). Клики мышью при `dpiAware: true` попадали (переключатель Properties). Без `dpiAware` на экране с масштабом больше 100 % клики идут мимо, но это известно по другим приложениям, в Revit не проверялось.
- Размер окна. `RevitApp` разворачивает главное окно при старте. Revit хранит нормальные границы окна и записывает их при выходе, поэтому тест, меняющий размер окна, обязан вернуть положение, которое прочитал в начале (контрактный тест свёрнутых панелей делает это в `AfterTest`).
- Скорость UIA. Полный обход дерева главного окна Revit с открытой моделью занимает около 75 с, а `DumpTree(40)` и `windows.txt` при падении теста занимают минуты (тесты с артефактами падения шли от 3 до 5 минут). Поиск по глубокому дереву (панель Properties, 5 повторных поисков) занимает минуты на тест. Не делайте дампов всего окна между действиями, зависящими от времени (см. свёрнутые панели).

## Ввод и ленточные элементы

- Сочетания клавиш зависят от языка ввода. `RevitApp.SendKeys` шлёт виртуальные коды в переднее окно Revit, а Revit сопоставляет сочетания по набранным символам. Два нажатия VK_P («PP») панель Properties не скрыли: через 15 с рамка оставалась на экране (файл `properties-pane-2022.txt` в коммите `22bd06a`, позже перезаписан прогоном переключателя ленты), на снимке экрана в этот момент была русская раскладка. Объяснение (сопоставление по символам) принято, прогон с английской раскладкой не делался. Команды Revit вызывайте через ленту.
- Панель Properties переключается кнопкой ленты `ID_TOGGLE_PROPERTIES_PALETTE` (вкладка Modify, панель `properties_shr`, Name «Properties», `RevitIds.Panes.PropertiesToggle`), и только кликом мыши: `TogglePattern.Toggle` и `LegacyIAccessible.DoDefaultAction` ToggleState не меняют и панель не переключают (`properties-toggle-2022.txt`). Скрытой панели в дереве UIA нет вообще (рамка исчезает, а не становится offscreen). Снова показанная панель лежит глубже: TabControl, TabItem, MFCPaneControl, HwndHost, Pane. Сетка свойств (Pane «GXWND») строк в UIA не выставляет: `Texts()` панели пуст, читается выбор элемента (ComboBox id `3119`).
- Лента AdWindows (`ribbon-2022.txt`). Вкладка и кнопка оба имеют `ControlType.Button` (ClassName «Button», паттерн Invoke), поэтому вкладку не отличить по типу и Name: «Modify» это и вкладка (id `Modify`), и кнопка панели Select (id `ID_BUTTON_SELECT`). Вкладка прямой потомок главного окна, рядом с ней лежит `<id вкладки>_PanelBarScrollViewer` с содержимым. Кнопки ищутся только в содержимом своей вкладки. Скрытые вкладки (редактор семейств) offscreen.
- Кнопки API имеют AutomationId вида `CustomCtrl_%CustomCtrl_%<вкладка>%<панель>%<имя PushButtonData>` (например, `CustomCtrl_%CustomCtrl_%TestHost%Test Runner%RunAllTests`), поэтому поиск по внутреннему имени работает. Подпись содержит перенос строки: `Run All\nTests` (LF, из PushButtonData), а у кнопок самого Revit `Project\r\nUnits` (CR LF). Дамп инспектора заменяет переносы пробелами, поэтому в нём «Project  Units». Библиотека сравнивает подписи, сводя переносы и пробелы к одному пробелу.
- Разделённая кнопка. «3D View» это две кнопки с одним Name: `ID_VIEW_DEFAULT_3DVIEW_FlyoutButtonShowFlyout` (Toggle) и `ID_VIEW_DEFAULT_3DVIEW_FlyoutButtonExecute` (Invoke). Меню раскрывается по AutomationId (`view-3d-2022.txt`).
- Выпадающие меню. У «Additional Settings» только Toggle (нет ни Invoke, ни ExpandCollapse). Меню это окно с ClassName UIA `Popup` (id `_PopupRoot`), внутри List, ListItem, Button с Invoke (`ribbon-pulldown-2022.txt`). Окно видно через `EnumWindows`, но его нет ни в `Windows.Popups()`, ни в `All()`: ленту эти окна ищет сама. Закрывается Esc, возврат Toggle меню не закрыл.
- Свёрнутые панели (`ribbon-collapsed-2022.txt`, `ribbon-collapsed-click-2022.txt`). Revit не сжимается уже 1063 пикселей (запрошенные 900×700 дали 1063×700). При этой ширине панель Manage, Settings свёрнута: Button id `settings_shr`, Name пустой, только Toggle, внутри Image `mCollapsedPanelImage`. Toggle раскрывает панель во всплывающее окно с ClassName UIA `Popup` и id `settings_shr_SlideOutPanelPopup_PopupRoot`. Кнопки в нём (Project Units, `ID_SETTINGS_UNITS`, паттерн Invoke) UIA сообщает offscreen с прямоугольником 0×0 даже через 5 с после появления окна, поэтому они нажимаются через Invoke, а не мышью. Окно панели закрывается само после нажатия кнопки (закрыто к первой проверке через 1,05 с или меньше после Invoke). В одном из прогонов оно исчезло само за 20 с, пока тест писал дампы (причина не выяснена). Состояние Toggle раскрытой панели ненадёжно (у Project Location окно было открыто при Toggle Off), поэтому раскрытость определяется по окну панели. Раскрытие, поиск кнопки и Invoke `RevitRibbon` выполняет подряд примерно за 2,3 с. В окне, развёрнутом на весь экран, кнопка Project Units лежит на панели без раскрытия (`ribbon-2022.txt`).
- `RevitRibbon.Click` для кнопки без Invoke использует Toggle, который у части кнопок команду не выполняет (известное ограничение, пример: переключатель Properties). Для них нужен клик мышью.

## Панели

- DockablePane (`panes-2022.txt`, `properties-pane-2022.txt`). Рамка это Pane с ClassName `Afx:ControlBar:…` и Name, равным заголовку. «Properties» прямой потомок главного окна (id `60164`), «Выбор по фильтру» лежит внутри TabControl, TabItem, MFCPaneControl, HwndHost. Тип Window для плавающих панелей в `RevitIds.Panes.FrameTypes` имеет уровень `[Г]`, плавающая панель не наблюдалась. Панель за невыбранной вкладкой AvalonDock («Project Browser: …») рамки в дереве не имеет, виден только заголовок вкладки (Text, id `mAnchorablerHeader`).
- Запомненная рамка панели. `DockablePanePage` запоминает найденную рамку и на каждом обращении проверяет, что `NativeWindowHandle` не 0, окно видимо (`IsWindowVisible`) и `IsOffscreen` равен false. Скрытая Properties исчезает из дерева, а её запомненная рамка при этом отвечает `IsOffscreen = false` (`closing-run-2022.txt`), поэтому одной проверки `IsOffscreen` недостаточно.

## Что не проверено

- Revit 2020 и 2024 (версия задаётся параметром `revitVersion`), Revit Server и облачные модели, несколько одновременно запущенных Revit.
- Ответ библиотеки на «Security - Unsigned Add-In» (в контрактных прогонах диалог не появлялся).
- Устаревание дерева UIA после смены вкладки модуля: в Revit не наблюдалось, способ обхода не документирован.
- Окна восстановления журнала Revit: во встроенном каталоге их нет. Если окно появится, уборка остановит тест с текстом окна, а запись нужно добавить в `knownDialogs`.
- «Close Project Without Saving» (модели совместной работы): запись каталога `[Г]`, вживую не встречалась.
- Ветка сворачивания панели «Toggle, затем Esc, затем ошибка» вживую не понадобилась. `RevitSession.End()` для Revit, запущенного самим сеансом, после последней правки конца сеанса (`ContractSession`) вживую не прогонялся. Тот же `Quit` проверен через `Attach_and_quit`.
